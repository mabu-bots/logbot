# 🔍 Discord ログ専用ボット（logbot）

p1228とは一切つながりを持たない、単体構成のログ専用ボットです。

| 項目 | 内容 |
|---|---|
| バージョン | v1.0.0 |
| 状態 | 本番稼働中 |
| 稼働先 | 台3 minase（pm2: logbot） |
| 実装 | TypeScript（Node.js 24+、discord.js 14） |
| 更新履歴 | [CHANGELOG.md](CHANGELOG.md) |

## 📖 概要

Go Gateway / Workers は使いません。TypeScript + discord.js の1プロセスで動きます。

## ✨ 機能

- メッセージ編集・削除、メンバー参加・退出、ロール変更、チャンネル作成・更新・削除、VC参加・退出・移動、VCミュート・デフ・配信、BAN・BAN解除をログとして通知します。
- **ログ種別ごとに通知先チャンネルを個別に設定できます。** 未設定の種別は通知しません（全体のデフォルトチャンネルはありません）。
- VCログ（`voice`）は他のログと別のチャンネルに送れます。ミュート等の状態変化は `voice_state` として分けてあるので、VC参加・退出だけ別チャンネル、ミュートは通知なし、といった分け方もできます。

### ログ種別（12種）

ログはEmbedで通知します。タイトルには種別ごとの絵文字（例：✏️ メッセージ編集、🗑️ メッセージ削除、👋 メンバー参加、🎙️ VC参加・退出・移動）が付き、フィールド名にも絵文字（👤 ユーザー、💬 チャンネル、📝 内容など）が付きます。フッターは `🔍 ログボット`、ヘッダーにはサーバー名が入ります。

| 絵文字 | 種別             | 内容                             |
| ------ | ---------------- | -------------------------------- |
| ✏️     | `message_edit`   | メッセージ編集（編集前・編集後） |
| 🗑️     | `message_delete` | メッセージ削除・一括削除         |
| 👋     | `member_join`    | メンバー参加                     |
| 🚪     | `member_leave`   | メンバー退出                     |
| 🎭     | `role_update`    | ロール変更・ニックネーム変更     |
| ➕     | `channel_create` | チャンネル作成                   |
| 🔧     | `channel_update` | チャンネル更新（名前変更）       |
| ➖     | `channel_delete` | チャンネル削除                   |
| 🎙️     | `voice`          | VC参加・退出・移動               |
| 🔇     | `voice_state`    | VCミュート・デフ・配信・ビデオ   |
| 🔨     | `member_ban`     | メンバーBAN                      |
| 🔓     | `member_unban`   | メンバーBAN解除                  |

### VC通話時間

VCログに通話時間が付きます。

- 参加ログ：参加時刻が付きます。
- 移動ログ：チャンネル移動してもタイマーはリセットされず、その時点までの経過時間が付きます。
- 退出ログ：**通話時間**（参加から退出まで）が付きます。例：`1時間23分45秒`、`45分12秒`、`32秒`。
- 通話中の確認：`/vc list` で通話中の全員と経過時間、`/vc time user:<ユーザー>` で指定した人の経過時間が、その場で正確に計算されて表示されます。

### VCチャンネルごとの通話継続時間

個人の通話時間とは別に、**チャンネルごとの通話継続時間**も計測します。

- チャンネルの通話は、誰もいないチャンネルに最初の人が参加したときに始まり、最後の人が退出したときに終わります。途中で人が入れ替わってもタイマーは続きます。
- 参加・移動・退出ログには **チャンネル通話時間** が付きます。最後の人が退出したときは、その通話の合計時間と「通話終了」が付きます。
- `/vc list` はチャンネルごとにまとめて表示します。各チャンネルの見出しにそのチャンネルの通話継続時間と人数が出て、その下に各人の経過時間が並びます。`/vc time` でも、その人の経過時間に加えてチャンネルの通話時間が出ます。
- チャンネルの開始時刻もSQLiteに保存しているので、Botの再起動でリセットされません。Bot起動前から通話が続いていたチャンネルは、個人の場合と同じく推定（Bot起動時から計測）になります。

### 参加時刻の手動設定（Bot起動前からの補正）

Botが起動する前から通話していた場合、参加時刻は分からないので推定になります。その実際の参加時刻が分かっているなら、`/vc set` で手動で設定できます。設定すると推定フラグが外れ、その後の退出ログや `/vc` の表示は手動の時刻から計算されます。設定した時刻はSQLiteに保存されるので、Botの再起動後も残ります。

```text
/vc set user:@終夜 time:2時間前
/vc set user:@終夜 time:17:00
/vc set channel:#雑談VC time:2026-11-14 17:00
```

- 時刻の書き方（日本時間）：`2時間前` / `1時間30分前` / `90分前` / `17:00`（今日、未来なら昨日扱い）/ `2026-11-14 17:00` / `11-14 17:00`。未来の時刻や30日より前の時刻は受け付けません。
- 対象は通話中の人・チャンネルのみです。参加していない人や通話していないチャンネルには設定できません。
- 時刻を偽れるため、`/vc set` はサーバー管理者（サーバー管理権限）のみ使用できます。`/vc list` と `/vc time` は誰でも使えます。

精度について：

- Botが参加を見届けた通話は、参加時刻をSQLite（`data/logbot.db`）に保存しているので正確です。Botを再起動してもタイマーはリセットされません（参加時刻は壁時計の時刻で保存しているため）。
- 移動しても参加時刻は変わらないので、合計時間は1回の通話として通算されます。
- ただし、Botが起動する前からVCにいた人は、Discordに参加時刻を聞く方法がないため、Bot起動時から計測を開始します。その場合は退出ログに「実際の通話時間より短い可能性があります」と注記が付き、`/vc` でも「（推定）」と表示されます。
- Botが止まっている間に退出・再参加した場合は、その間の動きは見られないため、起動時に古い記録は破棄されます。

## 📝 コマンド

`/log` と `/watching` はサーバー管理（Manage Guild）権限が必要です。`/vc list` と `/vc time`、`/ping` は誰でも使えます。コマンドの返信は埋め込みメッセージで、基本的に実行者にだけ見えます（限定表示）。

ただし `/vc list` だけは例外で、チャンネル全員に見える公開メッセージとして送られます。通話中の様子がみんなの話のタネになるようにするためです。

| コマンド | 権限 | 内容 |
|---|---|---|
| `/log set event:<種別> channel:<#チャンネル>` | 管理 | その種別の通知先を設定 |
| `/log disable event:<種別>` | 管理 | その種別の通知を止める |
| `/log list` | 管理 | 全種別の通知先を一覧表示（絵文字付き） |
| `/watching set text:<文言>` | 管理 | 視聴中ステータスの文言を保存（Bot全体、再起動後も維持） |
| `/watching show` | 管理 | 現在の視聴中ステータスを表示 |
| `/watching reset` | 管理 | 視聴中ステータスの保存文言を既定に戻す |
| `/vc list` | 全員 | 通話中の全員と経過時間を表示（公開メッセージ）。チャンネル名はタップでそのVCに飛べる表示で、各人の参加時刻と最長の人に 👑 が付き、最後に合計人数・チャンネル数・最長の人がまとめて出ます |
| `/vc time user:<ユーザー>` | 全員 | 指定した人の通話経過時間を表示（限定表示） |
| `/vc set user:<ユーザー> time:<時刻>` | 管理 | その人の参加時刻を手動で設定 |
| `/vc set channel:<VC> time:<時刻>` | 管理 | そのチャンネルの通話開始時刻を手動で設定 |
| `/ping` | 全員 | 応答確認 |

## 👀 プレゼンス

実際に表示されるプレゼンスは全Bot統一の**プレゼンス・サイクル**です。Playing で1分ごとに次の2つを交互に表示します（値は分の境界時点のものを境界の200ms前に先行送信します）。

- `<Bot名> | 起動して 1時間26分`（起点はログイン完了時）
- `<Bot名> | 現在時刻 19:24 JST`

`/watching` で保存される文言（既定 `ログを見守り中`、`.env` の `WATCHING_TEXT` でも変更可）は互換のため保存・表示対象として残りますが、実際に適用されるプレゼンスは常にサイクル形式です。`/watching show` は現在のサイクル表示を返します。

## 🚀 セットアップ

### 必要なDiscord設定

1. [Discord Developer Portal](https://discord.com/developers/applications) で**新しいアプリケーション**を作成し、Botを追加します（p1228のものは使いません）。
2. Bot設定で Privileged Gateway Intents を有効にします：
   - **Server Members Intent**（参加・退出・ロールログに必要）
   - **Message Content Intent**（編集・削除の内容表示に必要）
3. サーバーにBotを招待します。権限は「チャンネルを見る」「メッセージを送信する」「埋め込みリンク」で十分です。通知先チャンネルごとに送信権限があることを確認してください。
4. `.env.example` を `.env` にコピーし、`DISCORD_TOKEN` と `DISCORD_APPLICATION_ID` を設定します。

### 環境変数

| 変数 | 必須 | 内容 |
|---|---|---|
| `DISCORD_TOKEN` | ✅ | Bot のトークン |
| `DISCORD_APPLICATION_ID` | ✅ | アプリケーション ID |
| `DATA_DIR` | – | 設定（SQLite）の保存先（既定 `./data`、DB は `logbot.db`） |
| `LOG_LEVEL` | – | ログレベル（debug/info/warn/error、既定 info）。※現在はコードから参照されておらず、将来用に残している |
| `WATCHING_TEXT` | – | 視聴中ステータスの保存文言（既定 `ログを見守り中`） |
| `DB_BACKUP_ON_START` | – | 起動時に設定 DB のバックアップを作るか（`false` で無効化） |
| `DB_BACKUP_RETENTION` | – | DB バックアップの保持世代数（既定 10） |
| `DISCORD_GUILD_ID` | – | `clear:commands` でギルドコマンドを消すときに指定 |
| `DISCORD_GUILD_IDS` | – | `clear:commands` で複数ギルドを指定（カンマ区切り） |

### 起動

```bash
npm ci
npm run build
npm run sync:commands   # スラッシュコマンドを上書き同期（初回・コマンド変更時に実行）
npm start
```

開発時は `npm run dev` で起動できます。設定（通知先）は `data/logbot.db`（SQLite、Node標準の `node:sqlite`）に保存され、再起動しても残ります。Node 24以上が必要です。

> [!NOTE]
> `.env` は自動では読み込まれません。`DISCORD_TOKEN` / `DISCORD_APPLICATION_ID` はシェルに export するか、systemd の `EnvironmentFile=` で渡してください。起動前に `set -a; source .env; set +a` でも渡せます。pm2で起動する場合は `ecosystem.config.cjs` が `.env` を読み込むので、このままで大丈夫です。

## 🔄 運用

### pm2で自動起動

VPSの再起動後もBotが自動で立ち上がるように、pm2で管理します。

```bash
# 1. pm2をインストール（初回のみ）
npm install -g pm2

# 2. 最新版にしてビルド（.env が用意できていること）
cd ~/logbot
git pull
npm ci
npm run build
npm run sync:commands   # 初回・コマンド変更時のみ

# 3. pm2で起動
pm2 start ecosystem.config.cjs
pm2 status              # logbot が online になっているか確認
pm2 logs logbot         # ログを確認（Ctrl+Cで抜ける）

# 4. サーバー再起動後も自動起動するようにする
pm2 startup             # 表示されるコマンド（sudo ...）を実行する
pm2 save                # 現在のプロセス一覧を保存
```

よく使う操作：

```bash
pm2 restart logbot   # 更新後の再起動（git pull → npm ci → npm run build のあと）
pm2 stop logbot      # 停止
pm2 delete logbot    # pm2の管理から外す
pm2 logs logbot --lines 50   # 直近50行のログを見る
```

注意：

- `ecosystem.config.cjs` が `.env` を読み込んでBotに渡します。トークンはこのファイルには書かず、`.env` にだけ置いてください。
- Node 22では `node:sqlite` に `--experimental-sqlite` が必要ですが、`ecosystem.config.cjs` がNodeのバージョンを見て自動で付けます。Node 24以上なら不要です。Node 24への更新もおすすめです。

### コマンド同期（上書き同期式）

スラッシュコマンドの登録は `npm run sync:commands` だけが行います。Botの起動時には同期しません。

- 実行すると、現在のグローバルコマンド一覧を取得してから、`/log` `/watching` `/vc` `/ping` の4件で **PUTによる全置換** を行います。含まれていない古いコマンドは削除され、再起動で復活することはありません。
- 同期後に一覧を再取得して、実際の内容が期待通りか検証します。検証に失敗すると終了コード1で終了します。
- コマンドの定義を変えたら、必ず `npm run sync:commands` を実行し直してください。グローバルコマンドの反映には最大で1時間かかることがあります。

### 古いコマンドが残っているとき

上書き同期は **このアプリのグローバルコマンドだけ** を置き換えます。残っているコマンドは、まずどれかを確認してください。

| 残っているもの                       | 原因                                                                     | 対処                                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| logbotの古いグローバルコマンド       | まだ新しい `sync:commands` を実行していない、または反映待ち（最大1時間） | `npm run sync:commands` を実行し、`Removed:` に出るか確認。Discordクライアントを再起動（Ctrl+R）して反映を待つ                                    |
| サーバー限定（ギルド）コマンド       | ギルドコマンドは別エンドポイントのため、上書き同期の対象外               | 下の `clear:commands` を `DISCORD_GUILD_ID` 付きで実行                                                                                            |
| 前に使っていた別プログラムのコマンド | アプリケーションが違うため、logbot側からは消せない                       | 下の `clear:commands` を**旧プログラムのトークン／アプリケーションID**で実行する。旧Botがまだサーバーにいるなら、サーバーから追放するのも忘れずに |

全削除するには `npm run clear:commands` を使います。グローバルコマンドをすべて消し、検証します。

```bash
# logbotのグローバル＋指定サーバーのギルドコマンドを全削除
DISCORD_GUILD_ID=<サーバーID> npm run clear:commands

# 旧プログラムのコマンドを消す場合（旧アプリの認証情報で実行）
DISCORD_TOKEN=<redacted>
```

その後、logbotのコマンドを戻すには `npm run sync:commands` を実行し直してください。

## 📁 ファイル構成

- `src/index.ts` — 起動・Intents（コマンド同期はしない）
- `src/sync-commands.ts` — スラッシュコマンドの上書き同期（PUT全置換＋検証）
- `src/clear-commands.ts` — アプリケーションのコマンド全削除（グローバル＋ギルド）
- `src/events.ts` — 各ログイベントの検知と通知
- `src/commands.ts` — `/log` `/watching` `/vc` `/ping` の定義と処理
- `src/config.ts` — サーバー別・種別別の通知先と通話中のVCセッション（SQLite）
- `src/voiceSessions.ts` — VC通話時間の計測（参加時刻の永続化・経過時間の算出・起動時の補正）
- `src/logTypes.ts` — ログ種別の一覧・表示名・色
- `src/sendLog.ts` — 通知先へのEmbed送信（未設定なら送らない）
- `src/presence-cycle.ts` — 全Bot統一プレゼンス・サイクル
- `src/watchdog.ts` — READY停滞ウォッチドッグ
- `src/execLog.ts` — コマンド実行ログ（1行形式）
- `tests/` — 単体テスト（`npm test` でビルド後に実行）

## 📌 判断記録

- **v1.0.0 で再実装（2026-11-28）**：統一開発フローへの移行に伴い、旧 v0.1.2（パッケージ名 `discord-log-bot`）をゼロから書き直した。機能・コマンド定義・DBスキーマは本番スナップショットと機械比較で一致を確認している。経緯と旧→新対応表は [DESIGN.md](DESIGN.md) を参照。
- **パッケージ名を `logbot` に変更**：リポジトリ名に合わせた。pm2 アプリ名 `logbot` と DB ファイル名 `data/logbot.db` は運用互換のため据え置き。
- **dotenv は使わない**：旧実装からの据え置き。環境変数は pm2 の `ecosystem.config.cjs` が `.env` を読んで渡す。Bot 本体・同期ツールは `process.env` を直接読む。
- **`/watching` の保存文言と適用プレゼンスの分離**：保存文言（`watching_text`）は互換のため残すが、実際に適用されるプレゼンスは全Bot統一のプレゼンス・サイクル形式。旧テスト1件が統一前の形式（`/help | 42ms`）を期待して本番コードと食い違っていたため、本番コードを正としてテスト期待値をサイクル形式に修正した（詳細は DESIGN.md）。
- **`LOG_LEVEL` は未参照のまま残す**：旧実装でも `.env.example` と README に記載があるだけでコードから参照されていなかった。互換のため環境変数としては残し、未参照であることを明記する。
- **CI は1本に集約**：整形チェック→型チェック→ビルド→テスト→audit（参考）を `ci.yml` 1本で行う（[docs/ci.md](docs/ci.md)）。
